## What passed

- On the public candidate, Chromium 156 ran the small workspace through the real UI under both engines. Firefox 157 also passed under WASM64. The independent Sigima 1.4.1 checker found a maximum absolute error of **0** for every export. The invalid input left the previous objects and dirty flag intact; cancelling Save did not mark the workspace clean. Missing manifest: visible error and explicit restart, not an automatic fallback. WASM64 attempted no requests outside the site prefix in these A tests.
- The same WASM64 test and native oracle passed on the **private** tree. With 577 × 577 inputs, the actual `image:addition` command recorded `sigima.image.addition`; the three arrays totalled 5,326,864 bytes, with mismatch counts `[0, 0, 0]` and result extrema `[0, 4608]`. The first image, pair and result transferred exactly 1, 2 and 1 MiB respectively at each measured boundary. The small test passed again from an independent extraction of the ZIP following `npm ci`, without the developer checkout. This is not proof of any address above 4 GiB.
- 1,101 Vitest tests, 587 CPython application tests and four packaging tests passed. The frontend compiled, format, ESLint and the 1,477-key translation check passed. Stable initial JavaScript: 377.8 KiB gzip, below its unchanged 400 KiB limit. The stable tarball had 98 entries and no experimental runtime assets; the public demo has no private generator. Pyodide's iframe happy path and origin rejection passed (one pre-existing optional binary RPC test skipped).
- Same-origin coexistence passed again on the final static builds: the stable worker, demo Pyodide worker and stable main-thread Pyodide booted without any WASM64 requests. The default demo worker made 45 WASM64 requests. Confirmed demo reset preserved stable preference, trust, credential, cache, IndexedDB and OPFS witnesses.

Single-run ready times for the public candidate were 43,302 ms (Chromium/WASM64), 18,839 ms (Chromium/Pyodide) and 27,866 ms (Firefox/WASM64). These are neither medians nor a speed comparison. The memory peak or theoretical maximum of one engine must not be inferred from them. Raw local A logs and the dated smoke run with JSON and renderer CSV are under `build/wasm64/`; no user workspace is needed for reproduction.

## Reviewer and operator handoff

Dedicated Windows x64, Edge 158.0.4370.33: the corrected private build passed A (maximum absolute error 0), smoke, 2,048² and 8,192². The latter two had respectively 64 MiB and 1 GiB of resident arrays, with zero mismatches on both inputs and the full output. At 8,192² the result ranged from 0 to 65,528, the sampled renderer working set peaked at 2.62 GiB, and the UI tick occurred 4 ms into a 622 ms computation. Transfers remained 1 / 2 / 1 MiB at each boundary. The original build rounded epoch milliseconds in transit; the corrected test transmits them as decimal strings. Retain `build/wasm64/runs/2026-11-25T19-34-54.380Z-8192/report.json` as the predecessor on this machine and exact artifact. The final preflight at 20:35 returned 10.68 GiB of physical memory available and 21.44 GiB of remaining commit, below the required 16 GiB physical floor. There was no target allocation or OOM.
